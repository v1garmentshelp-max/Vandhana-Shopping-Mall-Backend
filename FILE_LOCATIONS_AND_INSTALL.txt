PROJECT ROOTS

Backend: vandhana-backend/
  Root marker: package.json + app.js + routes/ + services/
  Example: ZIP vandhana-backend/routes/orderManagementRoutes.js
           -> nee existing backend/routes/orderManagementRoutes.js

Website: vandhana-website/
  Root marker: package.json + src/ + vite.config.ts
  Example: ZIP vandhana-website/src/components/OrderHistory.tsx
           -> nee existing website/src/components/OrderHistory.tsx

Mobile: V1Garments-Mobile-Source/V1Garments-Mobile/
  Root marker: package.json + app.config.ts + app/ + src/ + android/ + ios/
  Example: ZIP V1Garments-Mobile-Source/V1Garments-Mobile/src/components/OrderCare.tsx
           -> nee existing mobile app/src/components/OrderCare.tsx

Admin: nee existing admin project root/
  Root marker: package.json + src/App.js + src/pages/NavbarAdmin.js
  Main ZIP lo vandhana-admin/ anedi admin changes folder label. Nee actual admin
  folder peru vere unte aa folder CONTENTS ni nee admin project root lo copy cheyyi.
  Separate vandhana-admin-Changed-Files.zip root lo src/ untundi; admin ROOT lo extract.

ZIP OPTIONS — OKA METHOD CHOOSE CHEYYI

1. V1Garments-Changed-Files-Correct-Paths.zip
   Recommended for your existing projects. Only changed/new code/config files.
   Extract to a temporary folder, open each project folder and copy its contents
   into the MATCHING existing project root. Confirm file replacement when asked.
   Do not put the whole ZIP inside backend/src or website/src.

2. Individual project source ZIPs / V1Garments-Correct-Structure-1.6.zip
   Backend, website and mobile are complete updated source copies without
   node_modules/build caches. Original folder names are preserved. Keep your
   existing environment configuration when copying into a project.
   Admin is clearly marked CHANGES ONLY because its full archive could not be
   opened; no original App.js/Navbar/login/stock/POS pages are overwritten.

Mobile source bundle lo V1Garments-Backend and V1Garments-Website copies kuda
same updated code tho sync chesanu. Actual deployment ki nee existing primary
vandhana-backend and vandhana-website projects ni use cheyyi. Same backend ni
two separate deployments ga create cheyyalsina avasaram ledhu.
V1Garments-Admin-Patch / V1Garments-Website-Patch are integration copies.
Historical notes under legacy-reference/ are not current installation steps.

    <Route path="/order-issues" element={<RequireAuth><OrderIssues /></RequireAuth>} />

If your actual App.js already has that route, no App.js change is required.
If it is absent, add only the import/route within your existing protected routing.
Keep the current App.js, NavbarAdmin.js and authentication providers.
If needed, add a Navbar link to /order-issues within your existing menu.
OrderIssues.js imports NavbarAdmin from ./NavbarAdmin, matching your supplied patch.
Do not replace App.js with a small sample app or the separate standalone order admin.

HTTP 502. It is not accurate to say you did not provide it or that the upload
necessarily failed. Admin relative paths above come from the supplied mobile

ENVIRONMENT / RUN ORDER

Backend existing environment: keep DATABASE_URL, JWT_SECRET and provider credentials.
.env.example is a sample. Never copy it over your real .env/environment values.
Set SHIPROCKET_WEBHOOK_TOKEN and the Razorpay webhook secret on the backend.
Admin token keys recognized: auth_token/admin_token/token/adminToken/accessToken.
Add your admin origin to backend CORS_ORIGINS. Branch tokens need branch_id.

Backend root (Node 24):
    npm ci
    npm run migrate:mobile
    npm run migrate:commerce
    npm run preflight:mobile
    npm run preflight:commerce
    npm start

Website root:
    npm ci
    npm run build

Admin root after copying these 3 files:
    npm ci
    npm run build

Mobile app root:
    npm ci
    npm run typecheck
    npm test

Deploy the migrated backend first, then website/admin, then test the mobile app.
The APK already delivered is still V1Garments-Android-Test-1.6.apk, build 7.
No code was changed for this packaging correction, so rebuilding that APK is
not required solely because folder names/file-location instructions changed.

Existing isolated verification: 75 backend + 19 mobile tests passed; website,
standalone order-admin and Android test APK builds passed. The original full
admin, live database/provider flows and native phone acceptance remain pending.
Read SETUP_AND_CHANGES.txt and API_AND_OPERATIONS.txt for provider setup/limits.
